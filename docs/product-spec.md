# 多人云端 Agent 协作网页：产品规格草案

更新：2026-10-26。状态：产品讨论稿。群聊与传输已有验证，网页自动提交云任务代码已实现；真实 OpenAI 托管云推理尚未验证。实现与证据见 [MVP 状态](../MVP-status.md)。

本文以本次对话中用户明确表达的需求为依据。「已确定」描述产品目标；「建议」仍需讨论，不代表用户已批准。暂称「同桌」，名称待定。

## 1. 产品定义（已确定）

围绕一个任务建立一个网页群聊房间。成员通过邀请加入，自选角色，可以彼此讨论，也可以用 @Agent 请求同一个 Codex 会话分析或执行任务。

网页及协作服务运行在发起人的 Mac，通过站点服务向受邀朋友提供访问。Codex 会话选择 OpenAI 托管的云端执行环境。Mac 负责产品服务和会话连接；Agent 的工作在托管环境中执行。

可以从任务创建时邀请成员，不要求先有正在运行的 Agent。第一版聚焦 Codex；试点内容是「兼容模式提案」及其审计背景。

## 2. 已确定的约束

- 用户目前使用订阅套餐，没有独立 API 额度，也没有自有云服务器。
- 目标执行端是 OpenAI 托管环境，不能未经讨论替换为自建云服务器或 Mac 本地执行。
- 独立网页，不接入飞书、Slack、企微等现有协作产品。
- 一个房间共享一个 Codex 会话，成员不是各自与独立 Agent 聊天。
- 成员填写昵称和角色后参与讨论；角色表达业务视角，例如设计者、开发者、评审者、使用者。
- 唯一自动启动 Agent 工作的交互是明确 @Agent。回复 Agent 问题、普通聊天、持续输入或停止输入都不自动触发推理。
- Agent 提问后，成员可连续讨论和补充；有人再次 @Agent 才继续。
- Agent 的控制权归房主；成员自选角色不改变这一归属。

## 3. 页面与主要流程

### 创建房间（流程建议）

房主填写标题、任务目标，添加共享资料，然后生成邀请链接。允许任务尚未开始时邀请同事。首次接入 Agent 时绑定一个已发布的 OpenAI 云端环境，之后点击网页「启动 Agent」，Mac 使用官方 Codex CLI 的订阅登录自动提交云任务；不再要求逐房间复制连接指令。

建议首版新建云会话，已有「兼容模式提案」会话用于整理经选择的背景与材料；直接绑定或迁移已有云会话是另一项接入能力，不能假定可用。

### 加入房间（需求已确定，访问规则待定）

受邀成员打开链接，填写昵称、自选角色，进入共享讨论。稳定的成员 ID 由服务生成；角色标签不是 system/developer 消息角色，也不自动授予操作权限。

### 房间页面（布局建议）

- 顶部：任务标题、邀请入口、会话连接状态。
- 主区：统一群聊时间线，人和 Agent 的发言有清晰身份标识，支持引用回复。
- 输入区：普通发言及 @Agent；提及是明确选中的 Agent 对象，引用或代码块里出现相同文本不触发。
- 任务侧栏：任务目标、成员与角色、共享资料、当前请求队列、Agent 产物。
- 云端环境由房主在房间设置中维护，首版建议创建后固定；更换环境应作为显式的新任务操作讨论。

### 唤起 Agent（触发原则已确定，调度细节为建议）

1. 所有发言先保存到房间时间线，保留成员 ID、显示名、当时的角色、消息 ID 与回复对象。
2. 普通发言不发起 Agent 工作。
3. @Agent 产生一个明确请求，记录请求者与对应消息。
4. 请求携带任务背景、资料、先前会话结果及截至该触发消息的相关人类讨论。
5. Agent 的回应与执行结果回到同一房间，关联该次请求，所有成员可见。

长历史可以压缩，但需保留已确认结论、争议、来源和后续纠正；聊天摘要本身不能把建议升级为共识。

## 4. 并发与状态（建议默认）

- 同一房间一次运行一个 Agent 请求，新的 @Agent 请求排队；人类群聊保持可用。
- 每次请求显示它处理到哪条群聊消息，不让成员误以为 Agent 已读到后来补充。
- 排队者可以取消自己的待执行请求；房主可以取消排队请求并停止当前执行。
- 失败请求保留错误与状态。提交结果不确定时先核对原请求，不自动重复创建任务。
- Mac 或连接不可用时明确显示状态。收到服务确认才显示「已发送」；不得把尚未接收的消息标记为成功。
- 云端任务状态、Mac 服务状态、群聊消息送达状态分别表达。

## 5. 成员与执行权限（房主控制已确定，细节待讨论）

房主掌握 Agent 控制权。当前 MVP 采用：房主负责环境、邀请、停止和重试；所有受邀成员均可聊天和 @Agent 提出请求。成员的请求等待房主批准，房主自己的请求直接进入队列。角色标签不改变执行权限。

建议试点范围为阅读提案、检索代码与资料、分析讨论、生成报告和材料。改源码、提交、推送和发布等行为需要另行确定执行边界；自选「开发者」等角色不构成这些行为的授权。

邀请建议采用可撤销的房间专属链接。首版是否需要口令、房主确认或完整登录，尚未确定。成员身份是昵称声明，不能据此声称已核验现实身份。

## 6. 历史、资料和产物（建议默认）

- 新加入者可见该房间全部共享历史和资料，入场前说明可见范围。
- 来源会话经房主选择后导入；不自动公开原私有会话的完整日志、工具输出和本地文件。
- 所有人均可补充共享资料，并记录添加者与来源。资料版本变化不静默改写既有结论的依据。
- Agent 输出中的报告、代码差异等以可查看的产物形式关联到请求；允许导出讨论记录和阶段结论。
- 源码和提案中的文本作为待分析材料，不能因其中含有命令或 @Agent 文本而自动执行。

### 文件传输（建议方案，链路尚未验证）

文件有两个不同的可用范围：房间成员可共享，和云端 Agent 已能读取。产品分别标记状态，不能把前者视为后者。

- 成员浏览器将原始文件上传到 Mac 上的房间文件服务；服务返回文件 ID、显示名、上传者、大小、版本和校验值，聊天消息引用文件 ID。
- 受邀成员经房间访问权限校验后预览或下载文件。站点服务必须能把文件上传、下载请求转发到 Mac；只提供静态页面不足以完成这条路径。
- 房主触发 Agent 时，服务绑定本次使用的文件版本，提供限定房间和文件范围、短时有效的 HTTPS 下载能力。云端执行工具从该地址取回文件并验证后，再标记为云端就绪。
- Agent 产生的报告等原始文件，通过限定到当前请求的 HTTPS 上传入口回传到 Mac 文件服务，完成后显示产物卡片供成员下载。不能只回传云端本地路径。
- 文件传输不使用群聊文本承载二进制，也不只保留文字提取结果；原始文件与可选的文本预览分开保存。
- 同名文件保留为新版本，正在执行的请求继续使用已绑定版本。上传附件本身不触发推理。
- 上传或回传失败时明确显示失败，校验完成后才标记成功；请求中应能看出实际使用了哪些文件版本。
- Mac 离线时该文件服务不可访问；需要明确提示文件当前不可用。

官方云环境文档说明可以配置访问外部域名，但这不等于已经验证本产品的文件传输。需分别验证访问入口、网络策略、鉴权、真实文件下载与原始产物回传，避免与单独计费的 Agents API 文件接口混淆。

## 7. 接入与部署状态：尚未验证

现有证据包括：本次讨论检查了本机 codex-cli 0.163.0 的 cloud 命令，具有 exec、list、status、apply、diff；cloud exec 可按环境 ID 发起新云任务。这未证明能持续读写同一个托管云会话。

以下是实现前必须验证的条件，不应写成已实现的产品能力：

1. Mac 程序以受支持的订阅登录方式创建或连接目标托管云会话。
2. 第一轮请求能获得正文与执行状态，而不只是任务 URL 或代码差异。
3. 第二轮进入同一个会话，保留前轮讨论与工作区状态；不是重建独立任务。
4. 不同成员的第三、第四轮请求能连续完成，不串到其他房间。
5. 断线后能恢复同一任务，并能确认之前请求是否已执行。
6. 确认所选站点服务可以向外提供邀请访问，并连接 Mac 上的业务服务。页面托管、消息存储和 Mac 连接方式不能混为一项已具备的能力。
7. 确认订阅账号用于该私人协作试点的支持范围；不能由单人登录成功推断多人共享调用已获支持。
8. 验证成员上传至 Mac、成员下载、云端取回、云端产物回传的完整文件链路，并核对原始字节一致性。

如果关键连接不可用，应明确报告阻塞，保留已经完成的产品设计；不默认改用另付费 API、自建服务器、浏览器抓取凭据或人工搬运消息。

## 8. 试点验收目标

- 房主创建「兼容模式提案」房间，选择共享的提案版本及背景。
- 至少两位真实成员从独立浏览器加入，显示各自昵称和角色。
- 成员连续互聊数轮，Agent 不因普通发言自动开始工作。
- 任一成员 @Agent 后，Agent 能区分发言者、引用讨论并给出与当前资料相关的回答。
- 后续另一位成员再次 @Agent，仍在原云会话及工作区继续。
- Agent 工作期间的新 @Agent 能按明确规则处理，状态对所有成员一致。
- 成员共同查看同一份产物；刷新页面后群聊与请求状态能够恢复。
- 一位成员上传文件，另一位成员能下载；Agent 实际读取同一文件版本，生成的原始产物能回传并下载。

早期草图只验证单机交互。当前 MVP 已通过双浏览器和公网文件传输验证，尚未满足真实托管云连续推理的验收项。

## 9. 建议优先讨论的决策

| 优先级 | 决策 | 建议起点 | 影响 |
| --- | --- | --- | --- |
| P0 | 同一个托管云会话能否持续接入 | 先做连续多轮最小验证 | 决定核心产品能否按约束实现 |
| P0 | 站点服务怎样让朋友访问 Mac | 先确定具体服务及其 Mac 连接方式 | 决定邀请链接是否可实际使用 |
| P1 | 是否接受 Mac 作为常开入口 | 接受时，离线明确提示，恢复后继续 | 决定房间何时可用 |
| 已确定 / P1 | Agent 控制归属及请求处理 | 房主控制已确定；成员 @ 请求的启动方式待定 | 决定协作自由度与执行控制 |
| P0 | 文件如何进入云端并回传 | Mac 房间文件服务，经 HTTPS 双向传输并校验 | 决定资料分析与产物共享能否完整工作 |
| P1 | 邀请和历史可见范围 | 私有邀请链接；入场后看房间完整共享历史 | 决定加入成本及分享边界 |
| P1 | 新任务还是已有会话 | 首版新会话，导入选定背景 | 降低原私有历史混入与迁移复杂度 |
| P1 | 并发请求与新补充 | 单房间单执行，@ 请求排队 | 保持共享工作区和上下文可解释 |
| P2 | 第一版交付物 | 提案讨论、阶段结论和可导出报告 | 防止试点扩展为通用协作平台 |

## 10. 暂缓范围（建议）

首版暂缓多 Agent、多模型后端、私聊、分支讨论、语音视频、自动插话、复杂组织权限和公开注册。后续按试点真实需要扩展。
